# Работа с Design Configurator

Это переиспользуемая оболочка выбора дизайна, а не лендинг конкретного продукта

- Сначала прочитай README.md и PROJECT-GUIDE.md
- Для нового продукта создай `projects/<id>/`, сохраняй примеры и core без изменений, если задача не требует изменения самой оболочки
- Первые варианты должны отражать исходный макет пользователя, остальные — осмысленные альтернативы
- Не переноси контент, логотипы, маршруты, контакты или юридические сведения другого проекта
- Решения, пресеты, контент и ресурсы описывай в адаптере проекта
- Каждое решение должно заметно и предсказуемо менять renderer, количество вариантов произвольное
- Не привязывай core к именам проекта, количеству секций, определённым токенам или трём вариантам
- Все файлы и шрифты должны собираться в автономный HTML из относительных путей
- Повышай revision при несовместимом изменении схемы выбора
- JSON импорта не должен выполнять код или менять проект, некорректный импорт не сбрасывает выбор
- Не добавляй отправку материалов во внешние сервисы, аналитику, аккаунты и публикацию без пользовательского запроса
- Не подключай зависимости, если задача решается существующей оболочкой и стандартным Node.js
- Запускай npm test и сборку нужного проекта, проверяй desktop/mobile, клавиатуру, импорт и HTML-экспорт
- Не публикуй секреты, личные материалы и dist в Git по умолчанию
- Предлагай production-перенос отдельным этапом, экспорт конфигуратора не является автоматически production-приложением

При просьбе «Используй наш конфигуратор» сохрани панель выбора, сравнение, масштабирование и экспорт, адаптируя только слой проекта
